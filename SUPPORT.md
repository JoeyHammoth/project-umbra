# Support

UMBRA is maintained by one person, on a best-effort basis. There is no support
contract, and no question is too basic — a confusing README line is a bug in the
README.

| I want to… | Go here |
|---|---|
| Ask how something works, or float an idea | [Discussions](https://github.com/JoeyHammoth/project-umbra/discussions) |
| Report something broken | [Bug report](https://github.com/JoeyHammoth/project-umbra/issues/new?template=bug.yml) |
| Request a capability or a slice of work | [Feature or task](https://github.com/JoeyHammoth/project-umbra/issues/new?template=feature.yml) |
| Report a security problem | [SECURITY.md](SECURITY.md) — privately, never in an issue |
| Contribute code, docs or a benchmark | [CONTRIBUTING.md](CONTRIBUTING.md) |
| Understand the physics or the algorithm portfolio | [docs/](docs) and the [wiki](https://github.com/JoeyHammoth/project-umbra/wiki) |

## Before you ask

- Search [open and closed issues](https://github.com/JoeyHammoth/project-umbra/issues?q=is%3Aissue)
  — the answer may already be there.
- The [roadmap](docs/ROADMAP.md) says what is deliberately not built yet. "The
  Design tab is empty" is the roadmap, not a bug.
- [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) covers the setup failures that
  actually happen: a missing `wasm32` target, a `wasm-bindgen` version mismatch,
  a blank page from the wrong base path.

## What to expect

Issues and pull requests are read in batches, usually within a week or two. If a
thread has gone quiet and it still matters, a polite ping is welcome — it is not
rude, it is the only notification the maintainer gets.
